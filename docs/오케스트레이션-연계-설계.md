# 오케스트레이터가 지휘하는 흐름 — 폴더의 수명과 빠진 자리

> 작성 2026-09-24. 지금까지의 DOE 는 **사람이 화면에서 누르는 것**을 전제로 만들어졌다.
> 오케스트레이터(기계)가 CAD 를 보고 DOE 를 만들고 해석까지 이어 거는 그림이 오면 무엇이
> 부족한지, 그리고 **공유 폴더가 쌓이는 문제**를 어떻게 다룰지 정한다.

## 0. 그림

```
오케스트레이터
  ① CAD 를 본다      ──MCP──▶ CompCore   search · work_geometry · recipe_find …  (있다)
  ② DOE 를 만든다    ──MCP──▶ CompCore   doe_preview · doe_create               (있다)
  ③ 끝났나           ──MCP──▶ CompCore   **없다** — 지금은 화면이 폴링한다
  ④ 내보낸다         ──MCP──▶ CompCore   doe_export → 폴더 경로                 (있다)
  ⑤ 해석을 건다      ──MCP──▶ SimEngBay  (그쪽 일)
  ⑥ 결과를 본다              SimEngBay 화면 — **우리에게 돌아오지 않는다**(결정)
  ⑦ 다 썼다          ──MCP──▶ CompCore   **없다** — 그래서 폴더를 못 치운다
```

**경계 한 줄: 데이터는 폴더로, 명령과 상태는 MCP 로.** 폴더에 상태를 적어 조정하지 않는다
(마커 파일 · 완료 표시). 두 곳에 상태가 있으면 어긋나는 날 **진실이 둘**이 된다.

## 1. 폴더가 쌓이는 문제 — 잰 값부터

```
설계점 한 점 = STEP 33 KB + topology.json 1.7 KB + conditions.json 1.5 KB ≈ 36 KB
   48점 →   144 파일 ·  1.7 MB        200점 →   600 파일 ·  7.1 MB
 1000점 → 3,000 파일 · 35.5 MB
```

**용량은 문제가 아니다.** 하루 10 스터디 × 200점이면 6,000 파일 · 70 MB/일 — 디스크는 견디지만
**폴더는 못 견딘다**(백업 스캔 · 탐색기 · 「이 폴더가 무엇이었나」).

### ① 공유 폴더는 보관소가 아니라 **전달 큐**다

정본은 서버 보관 폴더(`filestore/doe/…`)다. 공유 폴더는 해석이 읽어 가는 자리일 뿐이고,
**다시 만들 수 있다**(레시피 + 설계점 + 조건이 DB 에 있다). 운영 가이드도 이미 「백업 대상이
아니다」 라고 적어 두었다 — 그러면 **수명이 있어야 앞뒤가 맞는다.**

### ② 수명은 둘로 막는다 — 다 썼다는 신호 + 시간

| | 무엇 | 왜 셋 다 |
| --- | --- | --- |
| `doe_release(study_id)` | 오케스트레이터가 「다 읽었다」 | 지휘자가 아는 것을 말해 주는 것이 가장 정확하다 |
| 보관 기한(**기본 30일**) | 아무도 말 안 해도 지운다 | 오케스트레이터가 죽거나 사람이 손으로 돌렸을 때 |
| **영구보관**(스터디마다) | 기한이 지나도 남긴다 | **지우는 일은 되돌릴 수 없다.** 「이건 남겨야 한다」 를 아는 사람이 그때 켠다 — 기한은 기본값이고 예외가 규칙보다 세다 |

**다시 보내면 「다 읽었다」 는 무효다.** 안 그러면 방금 보낸 폴더가 다음 청소에 곧바로
치워진다 — 해석이 아직 열어 보지도 않았는데(시험이 잡았다).

지우는 것은 **공유 폴더의 사본뿐**이다. 서버 보관 폴더와 DB 는 남는다 — 다시 「보내기」 하면
같은 폴더가 다시 선다. 청소는 워커의 주기 작업(`doe.cleanup`)으로 돌린다.

### ③ 파일 개수 자체를 줄인다

- **점 파일 둘을 하나로.** `pNNNN.topology.json` + `pNNNN.conditions.json` → `pNNNN.json`
  (안에 `point` · `bodies` · `regions` · `conditions`). 3N → 2N 이고, 받는 쪽이 짝을 맞춰 읽을
  파일도 하나 줄어든다. **지금이 바꿀 적기다** — SimEngBay 는 아직 읽는 코드를 안 만들었다.
- **같은 형상은 한 번만 쓴다.** 조건만 훑으면(압력 2 · 3 MPa) STEP 이 전부 같다. `recipe_digest`
  가 같으면 `shapes/<digest>.step` 하나를 쓰고 점 파일이 그것을 가리킨다. 조건 훑기에서 파일과
  용량이 **N 배** 줄고, 받는 쪽은 「같은 메시를 다시 쓸 수 있다」 를 그 자리에서 안다.

## 2. 기계가 지휘하려면 빠진 것

### ① 끝날 때까지 기다려 주는 도구

`doe_create` 는 작업을 걸고 **즉시** 돌아온다(화면이 폴링하는 전제). 오케스트레이터는 폴링
루프를 제 쪽에 만들어야 하는데, 우리는 이미 `run_jig` 에서 **기다렸다 돌려주는** 모양을 쓴다.

    doe_run(work_id, factors, …) → 만들고 · 기다리고 · 내보내고 → {folder, points, failed}

한 번 부르면 다음 단계(SimEngBay 호출)로 갈 수 있는 것이 기계에게 맞다.

### ② 누구의 자격으로 부르나 — **여기서 가시성 결정이 강제된다**

오케스트레이터는 사람이 아니다 → PAT(서비스 계정). 그러면 그 DOE 의 소유자가 서비스 계정이
되고, 지금처럼 **개인 전용**이면 정작 사람이 못 본다(목록에 안 뜨고 403). 셋 중 하나를 골라야
한다:

| | 뜻 |
| --- | --- |
| **대행**(`on_behalf_of`) | 오케스트레이터가 「누구를 위해」 만드는지 밝히고 소유자를 그 사람으로 |
| **읽기 공개** | 소유자는 서비스 계정, 나머지는 본다 |
| **작업공간 소유** | 부서가 갖는다 |

**대행 + 읽기 공개**가 맞다고 본다 — 만든 책임은 사람에게, 보는 것은 모두에게.

### ③ 두 번 불러도 한 벌 — 멱등성

기계는 재시도한다. 같은 요청이 스터디 둘 · 폴더 둘을 만들면 해석 쪽은 **어느 것이 진짜인지
모른다**. `idempotency_key`(없으면 레시피 · 인자 · 시드의 다이제스트)로 **이미 있는 것을 돌려
준다.** 이것은 「만들기」 뿐 아니라 「보내기」 에도 있어야 한다.

### ④ 상태를 묻는 자리

`doe_status(study_id)` — 만드는 중 · 끝 · 몇 점 실패 · 폴더 경로(서버 경로와 해석이 여는
경로 둘 다). 지금은 `doe_points` 가 표 전체를 준다 — 기계가 진행만 보려고 200줄을 받는다.

### ⑤ 폴더가 자기를 말하게 — 누가 만들었나

`study.json` 에 **만든 사람**이 없다. 오케스트레이터가 만들면 더 필요하다 — 「이 폴더가
무엇이고 누가 시켰나」 를 폴더만 보고 알아야 한다(자기 설명적 원칙). `owner` ·
`requested_by`(대행이면 사람) · `created_at` 을 싣는다.

## 3. 그래서 할 일

| # | 무엇 | 크기 | 왜 이 순서 |
| --- | --- | --- | --- |
| 1 | `study.json` 에 만든 사람 · 대행자 | 작다 | 지금 폴더가 어기고 있는 원칙 |
| 2 | 점 파일 둘을 하나로(`pNNNN.json`) | 작다 | **SimEngBay 가 읽는 코드를 쓰기 전에** |
| ✅ 3 | `doe_release` + 보관 기한(30일) + 영구보관 + 청소 | — | 2026-09-24 |
| 4 | `doe_run`(기다려 주는) · `doe_status` · 멱등성 | 중간 | 기계가 지휘하는 최소 한 벌 |
| 5 | 가시성(대행 + 읽기 공개) | 중간 | 4 를 켜는 순간 필요해진다 |
| 6 | 같은 형상 중복 제거(`shapes/<digest>.step`) | 중간 | 조건 훑기가 흔해지면 |

1 · 2 는 **지금 하는 게 싸다** — 뒤로 갈수록 바꾸기 어려워지는 계약이다.

## 4. 아직 안 정한 것

- **오케스트레이터는 AI 다**(2026-09-24 확인) — local LLM 이 우리 PAT 을 들고 MCP 로 붙는다.
  그래도 MCP 에만 있는 편의(기다려 주는 도구 등)는 **API 에도** 둔다 — MCP 는 그것을 감싸는
  얇은 층이어야 하고, 그래야 AI 가 아닌 것이 붙는 날 다시 만들지 않는다.
- **해석이 실패했을 때 폴더를 지워도 되나** — 다시 돌릴 수 있어야 하므로 `release` 는 「성공」이
  아니라 「더 안 읽는다」 는 뜻이어야 한다.
