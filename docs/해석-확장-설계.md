# 해석 확장 설계 — 비선형 · 다물체 · 충격을 같은 조건으로

> 작성 2026-11-25 · **초안**(1단계를 시작하기 전, 받는 쪽과 계약을 맞추기 전). 결정은
> [ADR 0013](adr/0013-해석-조건을-케이스와-등록부와-능력표로-넓힌다.md). 바탕은 [해석-조건-설계.md](해석-조건-설계.md)
> (경계 · 선택 그룹 · 좌표계 · 단위 · `"=식"`)와 [동역학-조건-설계.md](동역학-조건-설계.md)(다물체의 칸 — 3단계가 그대로
> 쓴다). 이 문서는 **넓히는 뼈대와 단계**만 적는다.

## 0. 정한 것 (사용자, 2026-11-25)

- **받는 솔버**: CalculiX · Ansys 가 먼저. 다른 솔버도 붙일 수 있게 — 조건은 솔버를 모르는 중립 그대로, 솔버마다
  다른 것은 받는 쪽의 **능력표**(5장)와 번역이 맡는다.
- **순서**: ① 구조 정리 → ② 비선형 정적 → ③ 다물체 동역학 → ④ 충격 · 낙하.
- **그대로 두는 것**: 경계(메시 · 솔브 · 결과는 밖, ADR 0010), 서버의 사양표로 그리는 화면(`ConditionForm`),
  설계점마다 다시 푸는 선택 그룹 · 좌표계 · `"=식"`, 점 파일 · 픽스처 계약.

## 1. 지금 넓히는 것을 막는 것

| 막는 것 | 지금 | 넓힐 때 |
| --- | --- | --- |
| 해석이 하나 | 조건 한 벌에 `analysis` 하나. 앞선 해석은 초기조건 `prestress`(선행 정적 해석 이름)로만 잇는다 | 「예압 → 외력」 · 「동역학 반력 → 정적」 처럼 이어지는 해석이 흔해진다 |
| 종류의 갈림이 흩어짐 | 칸 39곳의 `only_for` 목록(`core/conditions.py` 2,947줄 — ①에서 패키지로 나눴다) | 종류 하나를 더할 때마다 수십 곳을 고친다 |
| 시간축이 없음 | 정적의 `steps` · `substeps` 숫자, 하중 안의 주파수 표 · PSD 표 | 비선형 · 충격 · 동역학은 모두 「언제 무엇이 걸리나」 가 핵심이다 |
| 재료가 값 묶음 | MatNexus 의 payload 를 그대로 나르고 탄성계수 · 푸아송비 · 밀도만 본다 | 소성 · 초탄성 · 변형률 속도 · 파손은 **어떤 재료 모델로 풀지** 정해야 한다 |
| 받는 쪽이 무엇을 받는지 모름 | 받지 않는 칸은 받는 쪽이 거절하거나 말없이 버린다 — 구조 해석의 「초기 온도」 를 손으로 막았다(2026-11-18) | 솔버가 늘면 칸마다 손으로 막을 수 없다 |

## 2. 공유 모델과 해석 케이스

```jsonc
{
  "schema_version": 2,          // 지금 1 — 판을 적는 칸은 이것 하나(`version` 은 레시피의 판)
  // 공유 — 한 벌
  "units": { … }, "frames": [ … ], "named_selections": [ … ],
  "materials": [ … ], "body_settings": [ … ], "contacts": [ … ],
  "curves": [ { "name": "예압 곡선", "x": "time", "points": [[0, 0], [1, 1]] } ],
  // 케이스 — 해석마다
  "cases": [
    { "name": "예압", "target": { "solver": "calculix" },
      "analysis": { "type": "static", … }, "constraints": [ … ], "loads": [ … ], "initial": [ … ],
      "outputs": [ … ] },
    { "name": "외력", "depends_on": "예압", "analysis": { … }, … }
  ]
}
```

| 공유 | 케이스 |
| --- | --- |
| 단위 · 좌표계 · 선택 그룹 · 재료 · 파트 설정 · 연결(접촉, 3단계부터 조인트 · 스프링) · 곡선 · 메시 힌트 | 해석 설정 · 단계(2단계) · 하중 · 구속 · 초기조건 · 출력 · 앞 케이스(`depends_on`) · 대상 솔버(`target`) |

- **옛 모양(v1)은 케이스 하나다.** 맨 위의 `analysis` · `loads` · `constraints` · `initial` 을 읽을 때 케이스 하나로
  편다. 케이스가 하나이고 받는 쪽이 v2 를 모르면(능력표의 `contract`) **v1 그대로 내보낸다** — 픽스처의 조건 ·
  영역 · 바디가 같아야 한다(시험 — 폴더의 바이트 비교는 스터디 id · 생성일 · STEP 머리글 때문에 못 한다). 케이스가 여럿인 조건은 저장은 되고, 받는 쪽이 v2 를 받기 전에는 내보내기가 까닭을
  말하고 막는다.
- **앞 케이스**: 초기조건 `prestress` 는 이 칸으로 옮긴다(옛 것은 읽어 옮긴다). 결과를 이어받는 것은 받는 쪽의
  일이다 — CompCore 는 「이 케이스는 저 케이스 뒤」 만 적는다. **한 사슬의 `target.solver` 는 같아야 한다** — 저장에서
  막는다(SimEngBay). 받는 쪽은 사슬을 작업 하나로, 무관한 케이스는 케이스마다 작업 하나로 푼다. 지금 이어지는 것은
  「같은 하중의 정적 → 모달」 하나이고 `prestress` 의 `from_step`(선행 정적 해석)은 거절된다 — 정적 → 정적은 ②에서.
- **앞 케이스의 뜻(SimEngBay 와 정함, 2026-11-26)** — 뒤 케이스는 앞 케이스의 끝 상태(변위 · 응력 · 접촉 상태)에서
  시작하고, 앞에서 조인 볼트는 조인 길이로 잠근다(v1 의 2단계와 같다). **하중은 이어지지 않는다** — 케이스의 `loads` 가
  그 케이스에 걸린 하중 전부이고 예외는 잠긴 볼트다. `target.solver` 가 비면 받는 쪽 작업의 솔버를 따르고, 다르면 받는 쪽이
  막는다. `analysis.solver`(풀이기 고르기)는 이것과 따로다.
- **사슬의 규칙** — 받는 쪽 첫 판이 막는 것을 CompCore 가 저장할 때 먼저 막는다(`cases._check_follows`, 오류는
  `cases[1].constraints: …` 처럼 짚는다).
  - **사슬만** — 한 케이스 뒤에는 하나. 갈래(예압 → 외력 A, 예압 → 외력 B)는 앞 케이스를 다른 이름으로 하나 더 적는다 —
    받는 쪽도 갈래마다 앞 케이스부터 다시 풀 생각이었으므로 잃는 것이 없다. 갈래가 실제로 필요해지면 연다.
  - 사슬 안의 **구속은 같다**(적은 차례는 상관없다) — 케이스마다 구속을 바꾸는 모델이 필요해지면 받는 쪽과 연다.
  - 앞에서 조인 볼트(같은 선택 그룹 · 단면 좌표계)에 **예압을 다시 적지 않는다**. 다른 볼트는 뒤 케이스에서 조여도 된다.
  - **앞 케이스는 정적만**(2026-11-27) — 모달 · 조화 · 랜덤에는 이어받을 끝 상태(변위 · 응력)가 없다(두 솔버 모두).
  - **케이스에서는 v1 의 선응력 칸을 쓰지 않는다**(2026-11-27) — 해석 설정 `prestressed` · 초기조건 `prestress` 를 케이스에
    적으면 막는다. 선응력은 앞 케이스가 말하고, 둘을 함께 두면 뜻이 갈린다(받는 쪽도 막는다). 화면은 케이스의 창에서 그
    칸을 내지 않는다(`withoutPrestress`). 케이스가 하나여도 같다 — 같은 것은 「정적 → 모달」 두 케이스로 적으면 v1 선응력
    모달로 접혀 나간다.
  - **대변형 · 초기 부단계 수는 정적 케이스끼리 같다**(2026-11-27, SimEngBay 와 같은 규칙) — 한 사슬은 해석 하나로 풀린다.
    CalculiX 는 NLGEOM 을 켜면 뒤 단계도 켜진 채이고, Mechanical 은 대변형이 해석 전체 설정이다. 하중 단계(②)의 부단계는
    단계마다라 따로다. 모달 · 랜덤에는 이 칸이 없다 — 「대변형 정적 → 모달」 은 두 솔버 모두 받는다(SimEngBay v2 판).
  - **뒤 케이스에서 처음 조이는 볼트**는 앞 케이스에서 풀린 볼트로 풀린다(Ansys 는 그 단계 앞에서 Open, CalculiX 는 기준점이
    자유) — 앞 케이스의 하중이 그 볼트에 기대면 기구가 되어 풀리지 않는다. 막지 않고 준비 점검에 알린다(`cases.ts`
    `looseBolts`). 같은 볼트는 (선택 그룹, 좌표계)로 가린다.
  - **중력은 정적 케이스끼리 같다** — 있고 없음, 방향(좌표계 포함). 하중이 이어지지 않으므로 케이스마다 같은 중력을 적는다.
    모드 해석 케이스(모달 · 랜덤)는 앞 정적이 끝난 상태의 중력을 쓴다 — 적지 않아도 되고, 적었다면 앞 정적과 같아야
    한다(2026-11-27 좁힘, SimEngBay 의 v2 설계안 5). 조화의 중력은 등록부가 막는다.
    솔버와 상관없이 막는다(대상 솔버가 비면 저장할 때 솔버를 모르고, CalculiX 만 받게 할 만큼 쓰임이 크지 않다).
    근거 — SimEngBay 실측(2026-11-26, Mechanical 2025 R2, 20 mm 상자 · 정적 두 단계): 중력은 끄는 칸이 없어
    (`EarthGravity` 에 `SetActivateAtLoadStep` 이 없다) 두 단계에 다 걸리고, 한 해석에 방향 하나다. **가속도 · 회전
    속도는 단계마다 끌 수 있어 막지 않는다** — 케이스마다 크기가 달라도 된다(받는 쪽이 케이스마다 걸어 풀고, 못 풀면
    작업을 만들 때 막는다). CalculiX 는 셋 다 단계마다 넣고 뺀다.
- **DOE**: 스터디는 케이스 전부를 스냅샷한다. 설계점마다 모든 케이스가 같은 형상 · 선택 그룹을 쓴다.
- **모델 · 점검 · 풀기를 넣었다(2026-11-26, `conditions/cases.py`)** — `Conditions.schema_version` 은 1 · 2,
  `cases[]` 는 `{name, depends_on, target: {solver}, analysis, constraints, loads, initial}`(출력 요청은 ②).
  - **케이스 보기**(`views` · `raw_views`): 케이스마다 공유 + 그 케이스 칸을 v1 모양 한 벌로 만든다. `parse` 는
    케이스마다 지금의 점검을 그대로 부른다 — 케이스 안의 규칙이 v1 과 하나도 다르지 않다. 케이스 칸의 오류는
    `cases[1].loads[0]: …` 로 짚는다(공유 칸의 오류는 그대로).
  - 케이스끼리: 판(케이스는 v2 에서만, v2 에는 하나 이상) · 섞임(케이스가 있으면 맨 위의 케이스 칸은 비운다) ·
    이름 중복 · 앞 케이스는 **앞에 적힌 것만**(없음 · 뒤에 있음 · 자기 자신) · 사슬의 `target.solver` 는 같다
    (빈 것끼리도 같다) · 사슬의 규칙(위 — 갈래 · 구속 · 다시 적은 예압 · 케이스마다 다른 중력).
  - `resolve`: 케이스 하나면 v1 그대로(시험 — 같은 케이스를 v1 로 적은 것과 dict 가 같다, `cases` 칸이 새지
    않는다), 여럿이면 「해석 케이스가 N개인 조건은 아직 내보낼 수 없습니다」 로 막는다 — DOE 만들기 · 고르기 인자
    점검이 그 말로 멈춘다. `resolve(…, cases=True)` 만 v2(공유 한 벌 + 케이스마다 v1 과 같은 길로 푼 칸)를 낸다 —
    v2 픽스처를 만드는 시험이 쓴다.
  - 따라 바꾼 곳: 식 알림(「케이스 ‘예압’ · 하중 ‘누름’ 크기」), 접촉 점검의 모달 알림(케이스마다, 같은 말은 한
    번), 고르기 인자(케이스가 하나면 그 케이스에, 여럿이면 아직 못 건다 — 케이스를 고를 칸은 내보내기가 열릴 때).
    조건 화면은 v2 를 케이스 탭으로 연다(6장).
  - **내보내기 스위치** — 설정 `doe_conditions_v2`(`.env` 의 `DOE_CONDITIONS_V2`, `auto` · `on` · `off`, 기본 `auto`).
    `auto` 는 **이 설치의 능력표 복사본**이 판 2 를 받을 때(모든 솔버의 `contract` 에 2)만 v2 로 낸다 — SimEngBay 의 판이
    나와도 운영에 올리는 시점은 운영자 일이라 판 번호가 아니라 그 설치가 실제로 받는 판으로 가른다(SimEngBay 와 정함,
    2026-11-27, `doe.services.conditions_v2`). `off` 는 강제로 끄고, `on` 은 시험 · 픽스처용이다. v2 로 낼 때 대상 솔버를
    비운 케이스의 결과를 바꾸는 칸 · 소성은 복사본의 모든 솔버가 읽어야 DOE 를 만든다(`capabilities.check_untargeted`). 점 파일의 다른
    칸 중 케이스를 보는 것(바디 예압 단면 점검 · 구조 물성 경고)은 케이스마다 본다. 픽스처 「조건_볼트예압_두케이스」 는
    시험만 켜고 뽑았다 — 영역 · 바디가 v1 「조건_볼트예압_정적」 점 1 과 같다.
  - **v1 한 벌로 접기**(SimEngBay 와 정함, 2026-11-27, `cases.fold_chain` · `model._folded`) — 스위치가 꺼져 있어도
    v1 한 벌과 같은 뜻인 두 사슬은 접어 내보낸다. 정적끼리의 사슬과 그 밖은 막는다.
  - **볼트 정적**: 「예압 → 외력」 정적 둘 — v1 의 볼트 정적이 바로 그 사슬이다(두 솔버 모두 ① 볼트 예압 + 중력 → ② 조인
    길이로 잠그고 나머지, 중력은 이어지고 강제 변위는 ① 부터). 하중 = 예압 + 외력(중력은 한 번), 구속 · 초기조건은 첫
    케이스의 것, 해석은 정적 `steps: 2`(받는 쪽은 읽지 않지만 v1 「조건_볼트예압_정적」 이 그렇게 적는다). 막는 것: 두
    케이스의 대변형 · 초기 부단계가 다름(v1 은 한 설정을 두 단계에 같이 건다), 단계 수 · 솔버가 기본값이 아님(받는 쪽이
    읽지 않는다), 「예압」 에 볼트 말고 다른 하중, 「외력」 에서 새로 조이는 볼트, 둘째 케이스의 초기조건, 정적 셋 이상.
    결과는 볼트 힘을 ① 끝 · 끝 따로, 변위 · 응력 · 반력은 끝만 낸다. 시험 — 「조건_볼트예압_두케이스」 를 접은 점 파일이
    지금 v1 「조건_볼트예압_정적」 점 1 과 같다(SimEngBay 실측: 「예압」 끝 볼트 1000 N, 「외력」 끝 1066.2 N, 바닥 -600 N).
  - **선응력 모달**: 「정적 → 모달」 사슬은 v1 선응력 모달(`prestressed: true` + 초기조건 `prestress`, `from_step` 비움)
    하나로 접어 내보낸다. 두 솔버 모두 같은 뜻이다(정적 끝의 응력 · 접촉 상태에서 모달, 볼트는 ① 조임 → ② 잠그고
    나머지 두 단계). 접히는 것은 둘뿐이다.
    - **정적 → 모달**: 하중 · 구속 · 초기조건 = 정적의 것(+ `prestress`), 해석 = 모달의 것 + `prestressed`.
    - **예압 → 외력 → 모달**: 「예압」 의 하중이 볼트 예압(+ 중력)뿐일 때 하중 = 예압 ∪ 외력(중력은 한 번) — v1 이
      두 단계로 나눠 푸는 그대로다.
    - 접지 않고 까닭을 붙여 막는 것: 앞 정적의 해석 설정이 기본값이 아님(v1 선응력은 읽지 않는다), 모달에 중력 말고
      하중 · 초기조건, 뒤 케이스의 초기조건, 「예압」 에 볼트 말고 다른 하중(v1 은 둘째 단계에만 건다), 「외력」 에서
      새로 조이는 볼트, 정적 셋 이상, 조화 · 랜덤으로 끝나는 사슬(받는 쪽이 케이스를 받는 판에서 읽는다).
    - 시험 — 「예압 → 외력 → 모달」 의 점 파일 조건 · 영역 · 바디가 지금 v1 「조건_볼트예압_선응력모달」 점 1 과 같다.
    - 접은 한 벌도 v1 으로 다시 점검한다.
  - **조화 응답의 선응력은 뺐다**(2026-11-27) — 두 솔버 모두 받지 않고 말없이 무시하고 있었다(SimEngBay 가 까닭을
    말하고 막도록 고친다). 해석 설정 칸 `prestressed` 는 모달 · 랜덤에만 있고, 조화의 초기조건 `prestress` 는 까닭과
    막는다. 랜덤의 선응력은 CalculiX 만 받는다 — 능력표가 가른다.
  - 아직: 옛 v1 선응력 모달을 케이스 사슬로 옮겨 읽기(받는 쪽이 v2 를 받는 판에서 — 그때까지 옛 조건은 그대로 둔다),
    DOE 인자의 케이스 고르기.
- **열어 둔 것**: 파트 설정을 케이스마다 덮을지(동역학의 강체 · 유연체와 구조의 변형체) — 3단계에서 정한다.

## 3. 해석 종류 등록부

- `conditions/registry.py` — 종류마다 {물리, 풀이, 이름, 받는 항목(구속 · 하중 · 초기조건 · 연결의 종류), 칸(어느
  모델의 어느 칸), 필요한 물성, 검증}.
- 칸의 `only_for` 는 등록부에서 만든다. **사양표(`spec()`)의 모양은 그대로**라 화면 · MCP 는 안 바뀐다.
  - **해석 설정의 칸부터 했다(2026-11-26)** — `registry.ANALYSES` 가 종류마다 이름 · 안내 · 쓰는 칸을 들고,
    `Analysis` 칸 15 곳의 `only_for` 와 `ANALYSIS_LABELS` · `ANALYSIS_NOTES` 를 거기서 만든다. 사양표는 `solver`
    의 `only_for` 차례만 바뀌었다(등록부 = 화면의 종류 차례, 읽는 쪽은 모두 「들었나」 만 본다). 등록부 · 모델 ·
    종류 목록 · 내보내는 칸이 어긋나면 `test_해석_종류_등록부가_칸의_only_for_를_만든다` 가 잡는다.
  - **받는 항목 · 물리도 옮겼다(2026-11-26)** — 종류마다 `accepts`(묶음 → 받는 종류, 능력표의
    `analyses.<종류>.loads` … 와 같은 꼴) · `needs`(하나 이상 있어야 하는 항목) · `item_fields`(그 종류에서만
    쓰는 하중 칸) · `physics`(구조 · 열 — 구조 물성 경고를 가른다) · `linearized`(접촉을 선형화 — 모달 · 조화 ·
    랜덤). 흩어져 있던 다섯 곳이 여기서 나온다: 가속도 PSD 는 랜덤에서만 · 랜덤에는 PSD · 고정 지지(옛
    `_check_excitation`), 바디 온도는 열에서만(옛 `parse` 안), 주파수별 배율 · 위상의 `analysis_only` · 비운 위상
    채우기, `material_warnings` 의 「열이 아니면 구조」, `contact_check.EIGEN_ANALYSES`. 저장할 때 막는 것은
    `model._check_accepted` 하나다 — 말은 「`loads[0]`: 가속도 PSD(기저 가진) ‘Z’은(는) 랜덤 진동(PSD) 해석에서만
    사용할 수 있습니다」 꼴로 몇 번째인지까지 말한다(옛 말은 PSD 에 번호가 없었다). 사양표 · JSON 스키마는
    바이트로 같다. 시험: `test_해석_종류_등록부가_받는_항목과_물리를_든다` · `…받지_않는_항목은_저장할_때_막는다`.
  - **막는 것은 그대로 옮겼다** — 안내만 하고 막지 않던 것(모달 · 랜덤의 「그 밖의 하중은 사용하지 않습니다」,
    열 해석에 실린 구조 하중)은 아직 받는다. 좁히면 저장된 조건이 막힐 수 있으므로 따로 정한다(후보 —
    능력표가 붙으면 대상 솔버마다 거르는 것으로 대신할 수도 있다).
  - 남은 것: 값 검증(모달 · 랜덤의 모드 수, 랜덤의 감쇠비, 과도의 끝 시간 — `_check_analysis` ·
    `_check_excitation`)은 칸의 값이라 그대로 두었다. 필요한 물성은 지금 물리 하나로 가른다(구조 = 탄성계수 ·
    푸아송비 · 밀도) — 종류마다(정적은 밀도가 중력 · 가속도에만) 나누는 것은 2단계의 재료 모델과 함께.
- 종류의 두 축: 물리(구조 · 열 · 기구) × 풀이(정적 · 과도 · 명시적 · 주파수 · 모달). 지금 여섯 종류(`static` ·
  `modal` · `harmonic` · `random` · `explicit` · `thermal`)는 그 자리에 등록한다. **비선형은 종류가 아니라 정적 ·
  과도의 옵션**이다(대변형 · 재료 모델 · 접촉 상태 — 2단계).

## 4. 곡선

- `curves[]` — 이름 · x 축(`time` · `step` · `frequency`) · 단위 · 보간(`linear` · `loglog` · `step`) · 점.
- 지금 하중 안의 `frequency_table`(조화) · `psd_table`(랜덤)은 그대로 받고, 곡선 이름으로도 가리킨다(`curve`).
  v1 받는 쪽에는 곡선을 풀어 하중 안의 표로 싣는다 — 받는 쪽은 바뀌는 것이 없다.
- 곡선의 점 · 배율에도 `"=식"`. 화면은 지금의 표 칸(`FrequencyTable` — 엑셀 붙여넣기 · Grms)을 넓혀 그래프를 단다.
- **모델 · 점검 · 풀기를 넣었다(2026-11-26, `conditions/curves.py`)** — `Conditions.curves`(공유)는
  `{name, x, unit, interpolation, points, scale}`, 하중의 `curve` 가 이름이다.
  - 곡선마다: 이름 중복 · 두 점 이상 · 가로축이 커지는 순서 · 로그-로그는 주파수 곡선에만(점 · 배율 > 0).
  - 쓰임(`USES`): 조화 응답 하중(`HARMONIC_LOADS`)은 `frequency_table` — 선형 · 단위 없음, 가속도 PSD 는
    `psd_table` — 로그-로그 · `g^2/Hz`. 주파수 곡선만, 표와 함께 적지 않는다. 그 뒤는 표를 채운 사본
    (`with_tables`)으로 지금의 점검을 그대로 — 해석의 주파수 범위를 덮는지도 같다.
  - 내보내기(`filled`): 식을 푼 뒤 점 × 배율을 하중 안의 표로, `curves` · `curve` 칸은 뺀다 — v1 · v2 모두 받는
    쪽은 바뀌는 것이 없다(시험 — 표를 적은 것과 dict 가 같다, 곡선이 없는 조건에는 칸이 새지 않는다).
  - 사양표 `curves`(칸 · 하중 종류마다 채우는 표 · 보간 · 단위 — `uses`), 하중의 `curve` 는 숨긴 칸.
  - **화면의 곡선 편집을 넣었다(2026-11-27, `CurveForm` · `CurvePlot` · `curves.ts`)** — 트리의 공유 갈래 「곡선」 과 리본의
    「곡선」 단추, 곡선 창(이름 · 쓰임 단추 — 가속도 PSD · 주파수별 배율의 보간 · 단위를 한 번에 · 가로축 · 보간 · 단위 · 배율 ·
    점 표 + 그래프 · 이 곡선을 쓰는 하중). 공유라 이름을 바꾸면 **모든 케이스의** 하중이 따라가고, 쓰는 하중이 있으면
    지우지 못한다. 하중 창의 표 아래에서 곡선을 고르거나(맞지 않는 곡선은 서버와 같은 까닭으로 막는다) **표를 곡선으로
    저장**한다. 곡선을 가리키는 하중은 그 곡선의 그래프를 보이고, 떼면 점 × 배율이 표로 옮겨진다(배율이 식이면 옮기지
    않는다). 준비 점검이 점의 문제(두 점 이상 · 가로축 순서 · 로그-로그는 0 보다 큰 점)와 없거나 맞지 않는 곡선을 짚는다.
  - **그래프**(`CurvePlot`) — 표 칸(`FrequencyTable`)에 단다. 로그-로그(PSD)는 두 축 모두 십진 눈금이라 규격의 dB/oct
    기울기가 직선으로 보이고, 선형은 0 을 품은 세로축, 계단은 다음 점까지 유지. 식이 든 점은 그리지 않고 센다. 가리키거나
    ← → 로 점의 값을 본다. 시험 규격의 PSD 표도 같은 그래프다.
  - 아직: 시간 · 단계 곡선을 하중이 가리키기(②의 하중 이력 — 저장은 된다), 곡선을 그대로 받는 판(받는 쪽과 ②에서).

## 5. 능력표 — 솔버를 더하는 자리

```jsonc
{ "receiver": "simengbay", "solver": "calculix", "version": "2.21", "contract": [1],
  "analyses": {
    "static": { "constraints": ["fixed_support", …], "loads": ["force", …], "contacts": ["bonded", …],
                "fields": { "analysis": ["large_deflection", "steps", …] },
                "materials": ["linear_elastic"] } } }
```

- **항목은 이름이거나 `{"name", "note"}`** — 조건부로 거절되는 것(예: Ansys 는 강체 파트 면의 하중을 거절)에 짧은
  설명을 단다. 종류 목록으로는 조건부를 다 적지 못하므로 **표는 1차 거르기**이고 최종 판정은 받는 쪽이 작업을 만들
  때와 모델링에서 한다.
- 받는 쪽이 자기 지원 목록 코드에서 만들고 시험으로 맞춘다. 지금 받는 해석은 모달 · 정적 · 조화 · 랜덤이고
  **`explicit` · `thermal` 은 없다.** 정적의 `steps` 와 `analysis.solver` 는 **지금도 말없이 안 읽힌다** — 표에 없으니
  「받지 않음」 으로 보이게 된다(SimEngBay, 2026-11-25).

- **받는 쪽이 솔버마다 낸다.** CompCore 는 케이스의 대상 솔버(`target`)로 저장 · 내보내기 때 거르고, 화면은 그
  칸 · 항목에 「이 솔버가 아직 받지 않음」 을 붙인다. 대상 솔버가 비면 지금처럼 거르지 않는다.
- **새 솔버 = 능력표 하나 + 받는 쪽의 번역** — CompCore 코드는 안 고친다(목표).
- 어디서 받나(정함): 받는 쪽의 `GET /api/simulations/capabilities`(솔버마다 하나, 같은 내용의 MCP 도구). CompCore 가
  관리 화면에서 갱신해 **복사본을 둔다** — 받는 쪽이 꺼져 있어도 저장이 막히지 않게.
- **더 정한 것(SimEngBay, 2026-11-27)** — 받는 쪽 갈래 `feature/capabilities` 에서 만든다.
  - 맨 위에 `receiver_version`(SimEngBay 판)을 더한다. `version` 은 솔버의 판(모르면 `null`).
  - 응답은 **늘 배열** — 설치가 받는 솔버마다 한 장. `?solver=` 를 주면 0 ~ 1장, 모르는 솔버면 빈 배열(오류 아님).
  - `fields.<묶음>` 은 **있으면 그 해석에서 그 묶음의 읽는 칸 전부**, 없으면 그 묶음의 칸은 거르지 않는다. 표에 없는
    칸은 「받지 않음」(지금 정적의 `steps`, 모든 해석의 `solver`, 조화의 `method`). `fields.loads` 의 예: 정적 · 모달
    `name · type · on · cs · magnitude · unit · direction · preload`(모달은 선응력의 앞 정적에 걸 때), 조화는 `preload`
    대신 `frequency_table · phase`, 랜덤은 `psd_table · grms`(Ansys 는 선응력이 없어 보통 하중 칸이 빠진다).
  - **CompCore 쪽에만 있는 칸은 이 목록으로 거르지 않는다** — 하중의 `curve` 는 내보낼 때 표로 풀려 받는 쪽에
    가지 않는다.
  - 모달 · 랜덤(CalculiX)의 보통 하중은 `{name, note: 「선응력을 켤 때 앞 정적에만」}` 으로 실린다.
  - 인증은 PAT(범위 `read`, `Authorization: Bearer <토큰>`, 토큰은 「<설치 이름>_pat_」 로 시작). 운영처럼 접두어가 붙은
    설치는 경로도 그 아래다. 계정이 막히면 토큰도 막힌다 — CompCore 전용 계정으로.
- **받는 쪽을 짰다(2026-11-27, SimEngBay v0.36.0 에 맞춤)** — 코어 `conditions/capabilities.py`(읽기 · 거르기 · 알림),
  복사본 `modules/server/capabilities_store.py`(서버 설정 표의 한 줄 `simengbay_capabilities` — 받은 그대로, 받은 때 ·
  사람은 그 줄의 것), 클라이언트 `shared/clients/simengbay.py`(`.env` 의 `SIMENGBAY_BASE_URL` · `SIMENGBAY_TOKEN`).
  견본은 `backend/tests/fixtures/simengbay/capabilities.json`(합의한 지문 4f179012… 에서 `receiver_version` 만 다르다).
  - **막는 것은 둘** — 대상 솔버가 정해진 케이스(v2)의 해석 종류가 표에 없거나, 묶음(구속 · 하중 · 접촉 · 초기조건)의
    항목 종류가 그 해석의 목록에 없을 때. 작업 저장(`works`)과 DOE 생성(고르기 인자의 값마다 포함)에서 막는다.
    접촉은 공유 칸이라 「케이스 ‘X’에서」 를 붙인다.
  - **알림** — `fields.<묶음>` 에 없는 칸에 기본값이 아닌 값(해석 설정은 그 종류가 내보내는 칸만), 항목의 `note`(종류마다
    한 줄). 준비 점검이 식 알림과 같은 길로 받는다(`/cad/conditions/notes` 에 고치는 케이스의 대상 솔버를 싣는다).
    받지 않는 항목도 거기서 먼저 경고로 보이고, 줄을 누르면 그 항목의 창이 열린다.
  - 거르지 않는 것 — v1 조건 · 접어 낸 한 벌 · 대상 솔버가 빈 케이스 · 복사본에 없는 솔버(준비 점검에 「확인하지
    않았다」 한 줄) · 복사본이 없을 때 · 하중의 `curve`. 재료는 정적에서만 재료 모델로 거른다(8장 「소성」).
  - 관리 화면 「서버 → 해석 쪽 능력표」 — 주소 · 마지막 갱신 · 솔버마다 판과 받는 해석 · 갱신. 실패하면 있던 복사본을
    두고 고칠 것을 말한다(401 `AUTH-0101` 은 토큰이 틀림 · 만료 · 폐기 또는 계정이 막힘 — 토큰을 바꿔도 안 되면
    SimEngBay 관리자에게, 403 은 범위, 404 는 접두어 · 옛 판). 오류 코드는 끝(`AUTH-0101`)으로 견준다.
  - 케이스 탭의 대상 솔버 목록이 복사본의 솔버다(판이 있으면 「Ansys 2025 R2」). 받은 적이 없으면 아는 둘.
  - 모르는 키는 버리고 읽는다 — v2 판의 `follows` · `contract [1, 2]` 가 붙어도 깨지지 않는다. 복사본에는 남는다.
  - **판마다의 견본**(같은 폴더) — `capabilities_v037.json`(SimEngBay v0.37.0 — `contract [1, 2]` · `follows`, 사슬은
    받고 단계 칸 · 소성은 아직 막는다), `capabilities_v038.json`(v0.38.0, 2026-11-28 — 정적의 단계 칸 넷 · 소성 재료
    둘을 받는다). 견본을 바꾸거나 더할 때는 **받는 종류 지문**(`version` · `receiver_version` 을 뺀 것, v0.38.0 은

### ② 비선형 정적 — 단계 · 하중 이력 · 수렴 · 출력 (SimEngBay 와 정함 2026-11-27, 코어를 짰다)

재료(소성)는 따로다 — MatNexus 의 응력-변형률 곡선은 **진응력** 기준(사용자, 2026-11-27). 변형률 축이 진(로그) 전체 변형률인지
소성 변형률인지는 아직 모른다(받는 쪽은 둘 다 소성 변형률 표를 받으니, 전체면 σ/E 를 뺀다 — ccx `*PLASTIC`, Ansys `MISO` ·
`TB,PLAS`). 소성 설계 요점에서 연다.

- **칸**(코어 `conditions/steps.py`, 모델은 `analysis.py` · `loads.py`):
  - 해석 설정(정적만): `load_steps: [{name, end_time, substeps: {initial, minimum, maximum}}]` — 비면 한 단계. 끝 시간은
    늘어나야 하고 비우면 단계 번호. 부단계는 최소 ≤ 처음 ≤ 최대, 셋 다 비우면 받는 쪽 기본. 쓰면 v1 칸 `steps` · `substeps` 는
    기본값이어야 한다. `convergence: {force_tolerance, displacement_tolerance, max_iterations, line_search, stabilization}` ·
    `outputs: {quantities, at: step_end | all | {count}}`(화면 기본 [변위, 응력, 변형률, 반력] · 단계 끝).
  - 하중(정적만): `time_table: [[t, 배율], …]`(힘 · 압력 · 모멘트 · 베어링 · 가속도 · 회전 속도 — 회전은 ω 에 곱한다, 양 끝 0 과
    마지막 끝 시간을 꼭 적는다, 선형 보간만, 곡선으로도), `active_steps`(적용 단계, 오름차순 — 중력 · 볼트는 못 쓴다, 배율 표와
    함께 쓰지 않는다), `bolt_steps`(볼트만, 단계 수만큼, `load` 는 맨 앞에 한 번, 나머지 `lock`).
  - 대변형은 단계가 아니라 해석 칸(`large_deflection`)이다 — 두 솔버 모두 단계마다 켜고 끄지 못한다.
- **뜻**(두 솔버 공통, 번역은 받는 쪽): 배율이 없는 하중은 첫 단계에서 0 → 크기로 오르고 유지. `active_steps` 는 처음 켜지는
  단계 안에서 0 → 크기, 꺼지는 단계 안에서 0 으로 선형으로 내린다(받는 쪽이 총 시간 배율표로 바꾼다). v1 볼트 정적
  (`steps: 2`)과 같은 뜻은 단계 둘 · 볼트 [load, lock] · 볼트가 아닌 하중 `active_steps` [2] · 중력은 모든 단계.
- **어디서 쓰나**: 해석 케이스에서만(케이스가 없는 조건에 적으면 저장에서 막는다). v1 으로 나가는 길(케이스 하나 · 접은 사슬)은
  ② 칸이 있으면 막는다 — 받는 쪽은 조건의 모르는 칸을 말없이 버린다. v2 로 낼 때(`doe_conditions_v2` — 위) ② 칸이 든 케이스는 하나여도
  v2 로 낸다. 쓰지 않는 칸은 내보내지 않는다(지금까지의 내보내기와 바이트로 같다 — 커밋된 픽스처가 그대로다).
- **능력표**: 결과를 바꾸는 칸(`load_steps` · `time_table` · `active_steps` · `bolt_steps`)은 `fields` 에 없으면 막고(곡선이
  채운 시간별 배율도), 수렴 · 출력은 알림이다. 받는 쪽은 v2 판 다음 판에서 이 칸을 `fields` 에 더한다.
- **사슬 ↔ 단계** — 「예압 → 외력」 은 둘 다 받는다(같은 덱). 화면이 권하는 길은 단계(한 해석 안의 하중 이력).
- **② 칸은 다른 케이스와 잇지 않은 정적 케이스에서만**(2026-11-28, 받는 쪽 첫 판 — 사슬 안의 어느 케이스든, 앞 케이스 자신도,
  SimEngBay 가 작업을 만들 때 SIMULATIONS-0046 으로 막는다) — 저장에서 먼저 막는다(`cases._check_staged_alone`). 결과를 바꾸는
  칸(하중 단계 · 시간별 배율 · 적용 단계 · 볼트 동작)만이고 수렴 · 출력은 막지 않는다. 화면의 「이어지는 케이스 추가」 는 하중
  단계를 옮기지 않고, 이은 케이스의 하중 단계 표는 「단계 추가」 를 막는다. 소성 재료의 「정적 → 정적」 사슬은 받는다(ε_p 가
  이어진다 — SimEngBay 실측).
- **픽스처**(`fixtures/simengbay/README.md` 「② 비선형 정적 픽스처」): 끝 모멘트 엘라스티카(닫힌 꼴), 사슬 ↔ 단계 맞대기,
