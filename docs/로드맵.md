# 로드맵

2026-09-18 에 정한 순서. 단계마다 **무엇을 만들고, 무엇이 되면 끝인지**를 적는다. 진행하면서
바뀐 것은 여기 고친다 — 이 문서가 「다음에 무엇을 하나」 의 정본이다.

## 구조 — 내 작업 공간에서 그려서, 등록으로 공개한다 (2026-09-18 에 다시 세움)

```
내 활동
  새 작업 ────▶ 내 작업 (내 작업 공간 · 나만 봄 · 형상 버전 + 지그 생성 기록)
                   │ 등록                       ▲ 내 작업 공간으로 복사
                   ▼                            │
공용        부품 카탈로그  ◀── 참조 ──  지그 카탈로그
            (불변 버전)                (불변 버전 · 어느 부품 버전의 지그인가)
```

| 화면 | 뜻 | 코드 |
| --- | --- | --- |
| 새 작업 | 빈 화면 · 템플릿 · 기존 작업의 사본 · STEP 에서 부품이나 지그를 그려 **새 작업으로만** 저장한다. 덮어 저장은 내 작업 › 수정의 일. 저장 전엔 아무것도 안 남는다 | `works/DrawPage` |
| 내 작업 | 그리고 있는 문서. 부품(레시피 버전) + 지그(옵션 · 실행 기록). **나만 본다**. 카탈로그의 부품 · 지그와 같은 말 — 다른 건 공개 여부뿐 | `works/*` |
| 실행 기록 | 내가 건 작업(형상 평가 · 지그 생성)과 산출물 | `jobs/*` |
| 템플릿 | 새 작업의 출발점. **내 템플릿 · 공용** 두 자리, 남의 것은 「내 템플릿으로 복사」 | `templates/*` |
| 부품 | 등록된 형상. 누구나 보고 「내 작업 공간으로 복사」 | `parts/*` |
| 지그 | 등록된 지그 + 어느 부품 버전의 지그인가 | `jigs/*` |

- 업로드한 STEP 도 `import_step` 노드 하나짜리 **버전**이다 — 제품은 늘 「이 작업의 형상」 하나다.
- 등록은 복사다. 카탈로그의 버전은 바뀌지 않는다. 고치려면 내 작업에서 고쳐 다시 등록(v2).
- 지그를 등록할 때 제품(그때의 형상 버전)이 부품에 없으면 함께 등록한다 — 지그만 있는 카탈로그는
  반쪽이다.
- 권한: 내 작업과 그 작업물은 소유자 · 관리자만. 등록된 작업물은 누구나(`jobs.require_visible`).
  관리자는 「관리 › 모든 작업」(`GET /works?owner=all|<사람 id>` — 태그 · 폴더도 같은 `owner`)에서
  남의 작업을 **검색한다**(2026-10-04). 여는 것은 원래 됐다 — 목록만 내 것이었다. 남이 `owner` 를 주면 403.
- 이전 구조(CAD 모델 · 지그 프로젝트)는 마이그레이션 0004 가 내 작업으로 옮겼다.

## 네 개의 명사

| 사람의 말 | 플랫폼의 명사 | 뜻 |
| --- | --- | --- |
| 작업 하나하나 | **작업(Job)** | 입력 + 옵션 → 실행 → 산출물. 종류(kind)가 있다: jig · cad · ai_cad … |
| 작업한 것의 목록 | **작업물(Artifact)** | 파일 하나. 어느 작업이 무엇으로 만들었나(계보)를 안다 |
| 내 작업 공간 / 공용 / 외부 API | **소유 · 공개 · 게시(Publish)** | private → shared → published(고정 ID · 불변 버전) |
| CAD 를 손으로도 AI 로도 | **모델(Model) = 레시피** | 형상을 만드는 연산 트리(JSON). 손그리기와 AI 가 같은 것을 만진다 |

**레시피가 핵심 결정이다.** CAD 를 메시 · STEP(결과)이 아니라 레시피(만드는 법)로 저장한다.
그래야 (1) 치수를 바꿔 다시 만들고 (2) 손으로 그린 것을 AI 가 고치고 그 반대도 되고 (3) AI 가
만든 것을 평가기로 만들어 보고 검증하고 (4) 버전 차이가 "fillet 3 → 5" 처럼 뜻을 갖는다.
외부 CAD 에서 온 STEP 은 `import_step` 노드로 레시피의 뿌리가 된다 — 처음부터 파라메트릭으로
만들라는 뜻이 아니라, **이 플랫폼에서 가한 변경을 기록하는 방식**이다.

## 1단계. 작업 · 작업물 · 워커 — 나머지 전부의 바닥 ✅ 완료 (2026-09-18)

왜 먼저: 지그 생성 · CAD 생성 · AI 생성 · 게시가 전부 "작업" 이다. 이게 없으면 기능마다 실행 ·
상태 · 목록을 따로 만든다.

- 표 `jobs`(kind · project · input · options · status · progress · summary · error), `artifacts`
  (job · kind · 파일 · 크기 · 부모 artifact)
- `JigRun` 을 `Job(kind="jig")` 로 흡수. 결과 파일이 `artifacts` 행이 된다.
- **워커** `python -m app.worker` — DB 를 큐로 쓴다(`FOR UPDATE SKIP LOCKED`). 별도 큐 서버 없음.
  API 는 즉시 `queued` 로 답하고 화면은 폴링. 개발에서는 `run.py` 가 워커를 자식으로 띄운다.
  `JOBS_INLINE=1` 이면 요청 안에서 동기로 돈다(시험 · 워커 없는 작은 설치).
- 화면: 「내 작업」 목록(상태 · 종류 · 산출물), 프로젝트 화면은 폴링으로 진행 단계를 보여 준다.
- 완료 기준: 지그 생성을 눌러도 화면이 안 멈추고, 목록에서 지난 작업의 STEP 을 다시 다운로드한다.
- ✅ 더한 것(2026-10-03 — **작업 멈추기 · 워커 상태**): 대기 중이면 바로 취소(조건부 UPDATE —
  워커가 막 집은 것을 「취소됨」 으로 적지 않게), 도는 중이면 `cancel_requested_at` 을 적고 워커가
  **단계마다**(진행을 적을 때) 보고 멈춘다 — 돌던 계산을 자르지 않는다. DOE 는 그때까지 만든 점과
  표를 남기고 「남은 설계점 이어서 생성」(`rerun?only=failed`)으로 잇는다. 워커는 따로 도는 줄에서 15초마다
  `workers` 표에 신호를 적고(마이그레이션 0026), 신호가 2분 끊기면 그 워커가 잡은 작업을 30분을
  기다리지 않고 되살린다. 서버 화면 「워커」 카드(상태 · 마지막 신호 · 하는 일 · 줄), MCP
  `cancel_job` · `doe_cancel` · `worker_status`.

  뒤집혔다 → 양쪽을 지어 보고 굽힘 반지름이 바로 나온 쪽을 고른다. ④ 숫자 칸에 소수를 한 글자씩 칠 수
  없었다(「1.」 → 1) → 치는 글자를 칸이 든다(`NumberText`). ⑤ 그 밖: 감춘 요소 형상 · 차수가 남아
  저장됨, 닮음 점수가 찾는 쪽에 따라 다름(구멍 짝을 두 목록을 함께 걸어), 잘못된 파트별 설정에
  500, 「모든 작업」 의 거르개가 주소와 어긋남, 형상에 없는 파트의 설정을 못 지움.
- 고친 것(2026-10-04 — 점검에서 남긴 것들): ① **판금 굽힘 점검**(서버 화면) — 고침으로 모양이 바뀌거나
  이제 생성되지 않는 판금 노드를 작업 · 부품 · 템플릿 · DOE 에서 찾아 작성자와 함께 보인다(바뀐 노드만
  지어 본다). ② **STEP 의 이름** — 문서는 ASCII `step_product` 를 약속했지만 한글이 그대로 나가 깨졌다 →
  `export.write_step` 이 이름을 바꾼 사본을 쓴다. 중간면 셸도 그 이름. ③ 「실행 기록」 에 관리자의
  「내 실행 / 전체 사용자」(요청자 열). ④ 작성자 고르개 · 계정 화면이 100명에서 잘리던 것 → 끝까지 잇는다.
  ⑤ DOE 미리보기 점의 인자 이름을 ‘’ 로(인자 이름이 「전체」 면 「전체 최소」 와 겹쳤다). ⑥ 판금 꺾은선의
  한 줄 위 가운데 점이 둥글리는 자리에서 터지던 것(굽힘이 아니므로 뺀다, 제자리로 되돌아가면 말한다).
- 더한 것(2026-10-04 — **설계 하나를 해석에 보내기**, SimEngBay 의 부탁): DOE 에 인자가 없으면 막았기
  때문에 「이 설계 하나만 풀고 싶다」 는 변수 하나에 값 하나인 DOE 로 우회해야 했다. 이제 **인자 0개 =
  지금 도면 그대로 설계점 하나**(빈 곱은 한 줄) — 폴더 계약이 같아 받는 쪽은 고칠 것이 없다. 작업 화면
  머리의 「해석용으로 내보내기」 가 그 DOE 를 만들고 DOE 화면으로 간다(내보내기는 거기서). MCP 는
  `doe_run(factors=[])`. 그런 DOE 에는 점을 더할 수 없다(DOE-0030 — 변수가 있는 새 DOE 다).

## 병행. 지그 코어 심화 ([지그-코어-심화-설계.md](지그-코어-심화-설계.md))

규격 부품 라이브러리(클램프 · 핀 · 받침 STEP 을 5단계 라이브러리에 게시 → 계획이 배치) ·
특징 인식 확장(경사면 · 옆 구멍 · 포켓) · 지그 편집(받침을 옮기면 간섭 재검사).

- ✅ **지그 편집**(2026-10-04): 요소 이름을 하나로(계획 · 미리보기 · 간섭 보고 · 레시피가 `받침_1` …),
  지그를 만들 때의 제품을 그 버전 · 받침 높이 변수에 걸어 편집기 미리보기에만 덧붙이고(`jig-product`)
  요소마다 간섭을 본다(`jig-check` — 걸린 요소는 빨갛게). 고른 요소를 3D 에서 XY 로 끈다. MCP
  `patch_work` 가 `jig_interference` 를 붙이고, `jig_check` 가 고치기 전에 본다.
- ✅ **특징 인식 확장**(2026-10-04): 경사면(`slope_up` / `slope_down` — 피했다고 말한다) · 옆
  구멍(축 X · Y — 바닥 구멍이 모자라면 **측면 위치 핀**, 받침대는 입구를 비킨다) · 포켓(사방이 벽 —
  클램프를 내리지 않는다). 화면 · MCP 가 「인식한 특징」 을 이름으로 보인다.
- ✅ **규격 부품 라이브러리**(2026-10-04, 설계 문서 3장): 시스템 관리자가 공용 부품에 규격 사양(받침 ·
  위치 핀 · 토글 클램프 — 품번 · 쓰는 버전 · 치수)을 붙인다(0033, 저장할 때 형상의 기준을 검사).
  판 · 클램프 고정이 요구에 맞는 것을 골라 `component` 로 놓고(받침 높이를 따라가는 변수는 식), 토글
  클램프는 도달 거리 · 방향 · 받침 블록까지 정한다. 결과에 **부품표**(품번 · 수량). 맞는 것이 없으면
  제작품으로 두고 말한다. MCP `set_standard_part` · `list_parts(standard=…)`.
- ✅ **규격 시험 3단계 — 일곱 더**(2026-10-05, `시험-규격-설계.md` 5.2): 숏빔 전단(D2344 · ISO
  14130), 압착(IEC 62133-2 · UN 38.3), 수압(IEC 60529 IPX7 · IPX8), 등가 정적 가속도(IEC 60068-2-27 ·
  ISO 16750-3 — 충격의 근사), 방향 하중(IEC 60335-1 코드 고정 · USB Type-C 렌칭 — 고른 면에 힘 ·
  모멘트), 구멍 · 핀 시편(D5766 · D6484 오픈홀, D5961 핀 베어링, D7332 뽑힘), 압축 시편(D695 · ISO
  604 · E9 · D6641 · ISO 14126).
- ✅ **규격 시험 2단계 — 바로 풀 수 있는 여섯**(2026-10-05, `시험-규격-설계.md` 5.1): 시편은
  인장(E8 · D638 I~V · ISO 527-2 도그본, D3039 · ISO 527-5 띠) · V 노치 전단(D5379 · D7078) · 접착
  겹치기 이음(D1002 · D5868 · ISO 4587) — 그립은 면 나누기 자리, 치수는 레시피 변수. 제품에는
  고유진동수(진동 응답 조사 · 자유-자유) · 적층 압축(무게 · 단수 · 계수) · 비틀림(끝 면 원격 변위
  회전) · 손잡이 · 벽걸이(고른 자리 고정 + 무게 배수). **제품 시험의 자리를 3D 에서 고른다** — 고정 면 ·
  누를 면(옆면도) · 비트는 끝. 화면의 표 · 편집 칸은 종류 정의(`kinds.ts`) 하나에서 읽는다.
- ✅ **전자제품 규격 시험 1단계**(2026-10-05, `시험-규격-설계.md` 5장): 보드 굽힘(JESD22-B113 ·
  IPC/JEDEC-9702) · 스마트폰 굽힘 예시를 굽힘 프리셋에, **제품에 거는 시험** — 정하중(IEC 62368-1
  T.2~T.5) · 정현파 진동(IEC 60068-2-6). 제품 레시피 그대로 + 하중 자리 · 구속 · 하중 · 해석 설정,
  물성은 제품의 것. 낙하 · 충격 · 랜덤 진동은 해석 쪽의 동적 · PSD 해석을 기다린다.
- ✅ **시험 규격 — 굽힘**(2026-10-04, ADR 0006 · `시험-규격-설계.md`): SpaceClaim 애드인의 시험
  프리셋을 옮기는 첫 단계. 공개 규격 13종(D790 · ISO 178 · D7264 · D6272 · C1161 · DMA 예시, 모두 「검토
  필요」)은 코드, 사내 규격은 DB(0034, 관리자). 규격으로 시편 + 지지 롤러 · 노즈 + 해석 조건(강체 ·
  고정 · 원격 변위 · 마찰 접촉 · 대칭점 · 대변형)이 붙은 내 작업 — 두께를 훑으면 간격 · 처짐이
  따라간다. 굽힘 지그 생성기가 같은 규칙과 4점 굽힘. 다음은 인장 → 압축 · CAI → 피로 · 이음.
- ✅ **규격 부품 옮기기**(2026-10-04, ADR 0005): 개발 PC 에서 고른 규격 부품을 묶음 파일(JSON)로
  내보내고 운영 서버에서 가져온다(관리자, 미리 보기 → 확인, 품번으로 짝지어 새 부품 · 새 버전 · 사양만).
  품번은 규격 부품 사이에서 하나. MCP `export_standard_parts` · `import_standard_parts`.

`app/` 에서 쓰는 이름을 build123d 의 모델링 모듈과 맞춰 센 것. 재보는 법은
`python - <<'EOF'` 로 `importlib` + 정규식 — 아래 표는 그 결과다.

| 모듈 | 쓰는 것 / 전체 | 안 쓰는 것 중 값어치 |
| --- | --- | --- |
| objects_curve (선 · 호) | 8 / 31 (26%) | CenterArc · JernArc — 중심 · 사이각으로 그리는 호 |
| objects_sketch (2D) | 12 / 14 (86%) | SlotArc(곡선 슬롯 — `path` 로 대신한다) |

쓰는 쪽이 적어 보이지만 안 쓰는 것의 대부분은 **한 가지를 그리는 여러 방법**(호를 접선 · 반지름 ·
사이각 … 으로 그리기)이다. 레시피는 그 중 하나만 고르면 된다. 다음에 값어치가 큰 것은 표의 굵은
글씨 — 도면 치수선(exporters 의 Drawing)과 실루엣(HLR).

2026-09-19 넷째 묶음에서 **AI 가 말로 받은 치수를 그대로 옮길 수 있는 것**(반지름 · 접선 호,
중심 사이 장공, 변 · 각 삼각형, 판금 절곡)을 먼저 채웠다 — 좌표로 환산하다 틀리는 일이 제일 많다.

## 순서의 이유

- 1 → 2: 큐 없이 레시피 평가를 붙이면 AI 편집(수십 초)에서 다시 뜯는다.
- 2 → 3 · 4: 그리기와 AI 는 같은 레시피를 다룬다. 3 과 4 는 바꿔도 되지만 폼 편집기(3-1)는
  AI 보다 먼저 — AI 결과를 사람이 고칠 수 있어야 한다.
- 5 → 6: 외부에 여는 것은 게시된 것뿐이다. 내 작업 공간의 작업 중인 것이 API 로 새면 안 된다.
