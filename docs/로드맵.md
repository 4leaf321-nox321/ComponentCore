# 로드맵

2026-09-18 에 정한 순서. 단계마다 **무엇을 만들고, 무엇이 되면 끝인지**를 적는다. 진행하면서
바뀐 것은 여기 고친다 — 이 문서가 「다음에 무엇을 하나」 의 정본이다.

## 구조 — 내 공간에서 그려서, 승격으로 내놓는다 (2026-09-18 에 다시 세움)

```
내 활동
  그리기 ─────▶ 내 작업 (내 공간 · 나만 봄 · 형상 버전 + 지그 생성 기록)
                   │ 승격                       ▲ 내 공간으로 복사
                   ▼                            │
공용        부품 카탈로그  ◀── 참조 ──  지그 카탈로그
            (불변 버전)                (불변 버전 · 어느 부품 버전의 지그인가)
```

| 화면 | 뜻 | 코드 |
| --- | --- | --- |
| 그리기 | 템플릿이나 STEP 에서 새 작업을 시작한다. 저장 전엔 아무것도 안 남는다 | `works/DrawPage` |
| 내 작업 | 그리고 있는 문서. 형상(레시피 버전) + 지그(옵션 · 실행 기록). **나만 본다** | `works/*` |
| 실행 기록 | 내가 건 작업(형상 평가 · 지그 생성)과 산출물 | `jobs/*` |
| 부품 | 승격된 형상. 누구나 보고 「내 공간으로 복사」 | `parts/*` |
| 지그 | 승격된 지그 + 어느 부품 버전의 지그인가 | `jigs/*` |

- 올린 STEP 도 `import_step` 노드 하나짜리 **버전**이다 — 제품은 늘 「이 작업의 형상」 하나다.
- 승격은 복사다. 카탈로그의 버전은 바뀌지 않는다. 고치려면 내 작업에서 고쳐 다시 승격(v2).
- 지그를 승격할 때 제품(그때의 형상 버전)이 부품에 없으면 함께 올린다 — 지그만 있는 카탈로그는
  반쪽이다.
- 권한: 내 작업과 그 작업물은 소유자 · 관리자만. 승격된 작업물은 누구나(`jobs.require_visible`).
- 이전 구조(CAD 모델 · 지그 프로젝트)는 마이그레이션 0004 가 내 작업으로 옮겼다.

## 네 개의 명사

| 사람의 말 | 플랫폼의 명사 | 뜻 |
| --- | --- | --- |
| 작업 하나하나 | **작업(Job)** | 입력 + 옵션 → 실행 → 산출물. 종류(kind)가 있다: jig · cad · ai_cad … |
| 작업한 것의 목록 | **작업물(Artifact)** | 파일 하나. 어느 작업이 무엇으로 만들었나(계보)를 안다 |
| 내 공간 / 공용 / 외부 API | **소유 · 공개 · 게시(Publish)** | private → shared → published(고정 ID · 불변 버전) |
| CAD 를 손으로도 AI 로도 | **모델(Model) = 레시피** | 형상을 만드는 연산 트리(JSON). 손그리기와 AI 가 같은 것을 만진다 |

**레시피가 핵심 결정이다.** CAD 를 메시 · STEP(결과)이 아니라 레시피(만드는 법)로 저장한다.
그래야 (1) 치수를 바꿔 다시 만들고 (2) 손으로 그린 것을 AI 가 고치고 그 반대도 되고 (3) AI 가
만든 것을 평가기로 만들어 보고 검증하고 (4) 버전 차이가 "fillet 3 → 5" 처럼 뜻을 갖는다.
외부 CAD 에서 온 STEP 은 `import_step` 노드로 레시피의 뿌리가 된다 — 처음부터 파라메트릭으로
만들라는 뜻이 아니라, **이 플랫폼에서 가한 변경을 기록하는 방식**이다.

## 1단계. 작업 · 작업물 · 워커 — 나머지 전부의 바닥 ✅ 완료 (2026-09-18)

왜 먼저: 지그 생성 · CAD 생성 · AI 생성 · 게시가 전부 "작업" 이다. 이게 없으면 기능마다 실행 ·
상태 · 목록을 따로 만든다.

- 표 `jobs`(kind · project · input · options · status · progress · summary · error), `artifacts`
  (job · kind · 파일 · 크기 · 부모 artifact)
- `JigRun` 을 `Job(kind="jig")` 로 흡수. 결과 파일이 `artifacts` 행이 된다.
- **워커** `python -m app.worker` — DB 를 큐로 쓴다(`FOR UPDATE SKIP LOCKED`). 별도 큐 서버 없음.
  API 는 즉시 `queued` 로 답하고 화면은 폴링. 개발에서는 `run.py` 가 워커를 자식으로 띄운다.
  `JOBS_INLINE=1` 이면 요청 안에서 동기로 돈다(시험 · 워커 없는 작은 설치).
- 화면: 「내 작업」 목록(상태 · 종류 · 산출물), 프로젝트 화면은 폴링으로 진행 단계를 보여 준다.
- 완료 기준: 지그 생성을 눌러도 화면이 안 멈추고, 목록에서 지난 작업의 STEP 을 다시 받는다.
- 남긴 것: 작업 취소 · 워커 상태(살아 있나)를 서버 화면에 — 필요해질 때.

## 2단계. CAD 레시피 — 모델의 표현 ✅ 완료 (2026-09-18). CAD 레시피 — 모델의 표현

- `core/recipe/` — JSON 연산 트리 + build123d 평가기. 연산: sketch(rect · circle · polygon ·
  line/arc) · extrude · revolve · cut · union · fillet · chamfer · hole · pattern · import_step · transform
- 표 `models`, `model_versions`(레시피 · 출처 손/AI · 메모). 평가는 Job(kind="cad").
- 지금의 `primitives.py` 4종은 레시피 템플릿이 된다. 지그 프로젝트의 「제품」 이 model 을 가리킨다.
- 완료 기준: 레시피를 POST 하면 STEP 이 나오고, 치수만 바꿔 새 버전을 만든다.
- 된 것: `core/recipe`(schema · evaluate · templates), `cad_models` · `cad_model_versions`,
  `Job(kind="cad")`, 미리보기 · 검증 · STEP API, 모델 목록 · 상세 · 버전 이력 · 되돌리기 화면,
  지그 프로젝트의 제품으로 모델 선택. 편집은 아직 JSON 텍스트(3단계가 폼 · 캔버스로 바꾼다).
- 남긴 것: `import_step` 노드를 화면에서 쓰는 길(STEP 업로드 → 작업물 → 레시피 뿌리) — 3단계에서
  「STEP 위에 구멍 하나 더」 를 할 때 붙인다.

## 3단계. 직접 그리기 — 레시피 편집기 ✅ 완료 (2026-09-18). 직접 그리기 — 레시피 편집기

1. 피처 트리 편집기(노드 목록 · 치수 폼 · 추가/삭제/순서) + 바꿀 때마다 glTF 미리보기
2. 2D 스케치 캔버스(SVG): 사각형 · 원 · 다각형 · 선/호, 치수 입력, 격자 스냅
3. 3D 에서 고르기: 면 클릭 → 그 면에 스케치, 엣지 클릭 → 필렛 (면 · 엣지 인덱스 ↔ glTF 대응표)
4. 실행 취소 = 버전 되돌리기
- 완료 기준: 마우스와 폼만으로 구멍 뚫린 L 브래킷을 처음부터 그려 STEP 으로 받는다.
- 된 것: 피처 트리 + 노드별 폼(`cad/recipeSpec.ts` 가 서버 스키마와 짝, 시험이 대조) · 스케치
  SVG 캔버스(놓기 · 끌기 · 격자 스냅 · 치수 폼) · 자동 미리보기(면 · 엣지 단위 메시
  `/cad/recipe/mesh`) · 3D 에서 면을 누르면 「그 면 위에 스케치」(PlaneSpec.normal) · 엣지를 누르면
  필렛/모따기 대상(EdgeNear — 인덱스가 아니라 중점 위치라 형상을 조금 고쳐도 살아남는다) ·
  id 를 바꾸면 참조가 따라옴 · 지우면 그것을 쓰는 노드도 함께 · JSON 토글.
- 남긴 것: 스케치의 치수 구속(두 도형 사이 거리 같은 것) · 3D 에서 면을 골라 구멍 위치 찍기 ·
  실행 취소의 「저장 전」 단계(지금은 저장이 곧 버전).

## 4단계. AI 로 추가 ← 다음

- `POST /models/{id}/ai-edit {"prompt": …}` → Job(kind="ai_cad"). 워커가 Claude API 를 부른다.
  도구: `get_recipe` · `propose_recipe` — 제안은 **반드시 평가기로 만들어 보고** 실패하면 오류를
  돌려줘 스스로 고치게. 특징 인식 결과(면 · 구멍 목록)를 컨텍스트로 준다.
- 결과는 새 버전 **후보** — 전/후 3D 를 나란히 보고 「적용」 해야 현재 버전. 출처 "AI".
- 완료 기준: "80×50×10 판, 네 모서리 M6, 모서리 R5" 를 치면 레시피와 3D 가 뜬다.

## 순서의 이유

- 1 → 2: 큐 없이 레시피 평가를 붙이면 AI 편집(수십 초)에서 다시 뜯는다.
- 2 → 3 · 4: 그리기와 AI 는 같은 레시피를 다룬다. 3 과 4 는 바꿔도 되지만 폼 편집기(3-1)는
  AI 보다 먼저 — AI 결과를 사람이 고칠 수 있어야 한다.
- 5 → 6: 외부에 여는 것은 게시된 것뿐이다. 내 공간의 작업 중인 것이 API 로 새면 안 된다.
