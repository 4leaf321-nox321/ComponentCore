# 0010. 해석 결과는 SimEngBay 가 보여 준다 — CompCore 는 설계점에 붙이지 않는다

날짜: 2026-10-22
관련: [해석 조건 설계](../해석-조건-설계.md) · [로드맵](../로드맵.md) 2단계 「실험계획(DOE)」 ·
`fixtures/simengbay/README.md`

## 결정

CompCore 는 **형상과 해석 조건까지** 만든다 — 치수 범위 → 설계점(STEP · 점 파일 · 조건) → 공유
폴더. 그 설계점을 푼 **결과(처짐 · 응력 · 반력 · 고유진동수 …)는 SimEngBay 안에 두고, 결과 표 ·
거르기 · 비교(파레토)도 SimEngBay 화면에서 본다.** CompCore 는 결과를 받아 설계점에 붙이지 않는다.

## 배경

로드맵은 2026-09-19 부터 「결과는 해석이 내고, 그것을 설계점에 붙이는 것이 다음 일」 이라고 적어
두었고, 그 자리(`DoePoint.metrics`, 결과로 거르기 · 파레토, MCP `doe_tradeoff`)를 빈 채로 남겨
두었다. 빈 답만 내던 그 자리는 `16016e5` 에서 이미 걷었다. 2026-10-22 남은 일을 정리하며 「결과를
CompCore 로 다시 가져올 것인가」 를 다시 물었다. SimEngBay 는 이미 CalculiX · Ansys 두 솔버로 같은
설계점을 풀어 서로 · 손셈과 견주고(셸 모델 픽스처, 2026-10-16), 결과는 그쪽이 가장 잘 안다.

## 대안

- **A. 결과를 CompCore 로 가져온다**(예: 같은 폴더에 `pNNNN.result.json` 을 SimEngBay 가 덧붙이고
  CompCore 가 읽어 설계점에 붙임). 고른 설계점을 바로 부품 버전으로 잇기 쉽고, CompCore 의 AI 가
  「조건을 만족하는 가장 가벼운 안」 을 답할 수 있다. 대신 결과 파일 계약 · 결과 칸의 모양 · 단위 ·
  솔버마다 다른 값을 어떻게 싣나를 두 플랫폼이 함께 맞춰야 하고, 같은 결과를 두 곳에 보여 주게 된다.
- **B. SimEngBay 에 둔다**(택함). 결과의 정본이 한 곳이고, CompCore 는 형상 · 조건의 정본으로 남는다.

## 결과

- 로드맵의 「설계점에 결과를 붙이는 것이 다음 일」 문장을 이 결정으로 바꿨다.
- 고른 설계점을 CompCore 로 되가져가야 할 때는 **설계점 번호**(`p0001` — 폴더 · 점 파일 · `number`
  가 같은 열쇠)로 짚는다. 결과 값이 아니라 그 점의 치수(`params`)가 형상을 다시 세운다.
- 나중에 A 가 필요해지면(예: CompCore 의 AI 가 결과로 고르게 할 때) 이 ADR 을 뒤집는 새 ADR 로
  계약부터 정한다.
